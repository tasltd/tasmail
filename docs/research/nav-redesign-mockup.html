Redesign Overview

Problem: Current sidebar has 41 flat settings buttons, all at same visual weight as Inbox. New users can't find email.

Solution: Group into 5 buckets: Mail (FolderTree), Apps (Calendar/Contacts/Tasks/Templates), User Settings (one gear button), Admin (gated), Quota.

Key Changes

  • Compose remains top CTA — large, blue, unmissable
  • Inbox is folder #1 with unread count badge (e.g., "3")
  • Default folders (Sent, Drafts, Spam, Trash, Archive) visually dominant
  • Apps section: Calendar, Contacts, Tasks, Templates as peer top-level entries (users expect these as separate surfaces, not forms)
  • Settings = single gear icon opens a Settings Hub page with 8 left-rail tabs (Account, Mail, Notifications, Security, Storage, Appearance, Integration, Billing)
  • Admin section visible only when user.isAdmin === true; holds LDAP, SAML, OIDC, DLP, eDiscovery, Retention, Webhooks, Plugins, ActiveSync, CalDAV, Ollama, Rspamd, DANE, Hostnames, SMTP, Deliverability, Billing, Branding
  • Quota bar stays at bottom (shows storage usage, 0–100%)

Settings Hub Structure

When user clicks the Settings gear, they navigate to /settings which renders a full-page Settings Hub with left-rail tabs:

Account: IMAP/SMTP config, Encryption, Change Password

Mail: Signatures, Filters, Templates, Spam Rules, Auto-reply/Vacation, Shared Mailboxes

Notifications: Push Devices, Email Frequency, Do-not-disturb quiet hours

Security: 2FA (TOTP, SMS, WebAuthn), Login Activity, Sessions, Bandwidth limits

Storage: Quota, Archive policy, Retention rules, Migration

Appearance: Theme, Font size, Sidebar collapse/expand, Density

Integration: CalDAV/CardDAV, POP3 access, Shared Files, AI Config

Billing: Subscription, Invoices, Usage breakdown

Admin Visibility Logic

Admin section only renders when useAuth().isAdmin === true. In the sidebar, this means:

const { isAdmin } = useAuth(); return ( <aside className="sidebar"> <!-- ... Compose, FolderTree, Apps, Settings ... --> {isAdmin && ( <div className="nav-section"> <div className="nav-section-title">Administration</div> <!-- Admin items here --> </div> )} </aside> );

Same pattern as the existing RequireAdmin component in frontend/src/components/admin/.

Empty-Inbox UX

When user opens Inbox with no messages:

You're all caught up!

Emails from your IMAP server will appear here.

This mirrors Gmail, Outlook, Zoho, FastMail, ProtonMail.

First-Login Tour (Optional)

3-step lightweight tooltip tour on first login (dismissible, re-trigger via Help menu):

  1. Compose button: "Click here to write a new email"
  2. FolderTree: "Your emails are organized in folders. Check Inbox for incoming mail."
  3. Settings gear: "Customize your experience: signatures, filters, security, and more."

Uses react-joyride or similar; tracked via localStorage hasSeenTour so it only shows once.

Keyboard Shortcuts

Preserve existing shortcuts in useKeyboardShortcuts hook:

  • g i → Inbox
  • g s → Sent
  • c → Compose
  • ? → Help (shortcuts modal)
  • g e → Settings (new; mirrors Gmail)

Migration Path

  • Week 1: Build navConfig.ts + SettingsHub component + admin gating. Run npm run trace-check.
  • Week 2: Consolidate 8 user-facing settings managers into SettingsHub tabs. Test each tab.
  • Week 3: Fold admin routes into sidebar (visible only to admins). Add keyboard shortcut tests.
  • Week 4: Empty-inbox copy + optional first-login tour. Mobile QA (sidebar collapse/expand).
