### 3. shadcn primitives — owned-source pattern, no central registry

48 shadcn components live under `src/components/ui/`. This matches the standard
shadcn convention (you "own" each component file; there's no NPM dep to bump).
There is **no `components.json`** — i.e. the shadcn CLI (`npx shadcn add <name>`)
was *not* used and would need to be initialised before any new primitives can be
pulled in via the CLI. All 48 are committed as hand-maintained files.

`src/components/ui/utils.ts` exposes the standard `cn()` helper (`clsx` +
`twMerge`). No barrel `index.ts` — every consumer imports the specific file
(`import { Button } from '@/components/ui/button'`), which is what enables Vite's
tree-shaking to drop unused primitives. **No change needed here** — the
"registry-driven" question in the original ticket is a false alarm; shadcn's
deliberate non-registry-ness is the right pattern for the alt-UI's brief.

Observations worth noting (not action items):
- `src/components/figma/ImageWithFallback.tsx` exists but is never imported.
  Likely a leftover from the Figma Make export. Safe to delete.
- `use-mobile.ts` is imported by `sidebar.tsx` only. Fine.

### 5. Build pipeline — no caching, full overwrite every run

`scripts/build-alt-ui.sh` is 32 lines and intentionally simple:

```bash
( cd "$SRC" && npm install --no-audit --no-fund --silent )   # always runs
( cd "$SRC" && npm run build )                                # cold vite build
rm -rf "$DEST"                                                # wipes /modern/
mkdir -p "$DEST"
cp -r "$SRC/dist/." "$DEST/"
```

Issues:

| Step | Issue | Fix |
|---|---|---|
| `npm install` | No `package-lock.json`-only mode; runs the resolver every time | Switch to `npm ci` (deterministic, ~3× faster on clean cache, fails fast if lockfile drifted) |
| `vite build` | Default `.vite/` cache lives in `node_modules/.vite/` and *is* reused across runs, BUT the gitignored bundle output has no content-hash short-circuit | Hash-compare `$SRC/dist` against `$DEST` before `rm -rf` — skip the copy + git churn if identical |
| `rm -rf $DEST && cp -r` | Always rewrites `frontend/public/modern/{index.html, assets/*}`, which are git-tracked | Either gitignore the output, or compare-then-copy |

A worked example: today, **running the script on `main` with no source changes**
produces a *different* `index-*.js` filename hash on the next checkout because
Vite re-emits with a new ID (depending on Node version / install order), making
`git status` dirty for no semantic reason. The TMAIL-261 PWA assessment (which
landed in the same wave as this audit) flagged a similar churn risk for the
classic SPA's service-worker registration; same shape of fix.

### 6. Auth gate — minimal and correct, but the redirect loops

`AuthGate` (`src/app/App.tsx:12–33`):

```tsx
useEffect(() => {
  const token = localStorage.getItem('access_token');
  if (!token) {
    window.location.href = '/login?next=/modern/';
    return;
  }
  apiClient.setToken(token);
  setReady(true);
}, []);
```

- ✅ Defers to the classic SPA's `/login` page — no second login form.
- ✅ Uses `apiClient.setToken()` rather than reading `localStorage` on every
     request inside the client (the client *also* re-reads `localStorage` in
     `tryRefresh()`, which is fine).
- ❌ Does not check `claims.exp` before declaring the gate cleared. A user
     loading `/modern/` with a 2-hour-stale token will see the UI flash before
     the first API call returns 401 and the in-`tryRefresh` flow kicks in. Cheap
     fix: add `if (claims.exp * 1000 < Date.now()) { redirect; }` before
     `setReady(true)`.
- ❌ The `?next=/modern/` query param is **not consumed** by the classic
     `LoginPage.tsx` — verified by grep. Post-login the user lands on `/app`
     (the classic mailbox). Either:
     - Make `LoginPage` honour `?next=`, **or**
     - Have `AuthGate` store the intended return-to in `sessionStorage` and
       have `LoginPage` redirect there on success (more invasive).

The duplicate JWT-decode logic (`src/lib/jwt.ts` vs
`frontend/src/components/admin/RequireAdmin.tsx`) is the same DRY concern as
finding #2 — solve it as part of the shared-package extraction.

### 7. HashRouter — typing minimal, scope tiny

```ts
export const router = createHashRouter([
  { path: "/", Component: Root, children: [
    { index: true, Component: EmailClient },
    { path: "admin", Component: AdminDashboard },
    { path: "calendar", Component: CalendarView },
  ]},
]);
```

Only **3 routes**, only **3 `Link` callsites**. Untyped strings here are
low-risk in absolute terms, but the same pattern in the classic SPA was the
seed of TMAIL-260 finding #10 — a registry-driven nav set is both
the a11y win and the scalability win.

Recommendation: extract `src/app/paths.ts`:

```ts
export const PATHS = {
  mail: '/',
  admin: '/admin',
  calendar: '/calendar',
} as const;
export type PathKey = keyof typeof PATHS;
```

Then every `<Link to={PATHS.admin}>` is typo-proof and rename-safe. Cost:
~5 lines of code plus 4 file edits.

### 8. Bundle size — single 456 kB chunk, overlaps the classic SPA

Current build output:

```
themes/shadcn-prototype/dist/assets/index-Ce6-HA2Z.js   456 kB
themes/shadcn-prototype/dist/assets/index-BmhaDO0a.css  100 kB
```

That ships **on first navigation to `/modern/`** even if the user only wants
the inbox. No route-level `React.lazy()` for `AdminDashboard` (heavy: 8 lucide
icons, 4 queries) or `CalendarView` (heavy: shadcn `calendar.tsx` + `react-day-picker`).

**Worse**, the user has *already* downloaded:
- React 19, TanStack Query 5, DOMPurify, date-fns (in `frontend/`)
- React 18, TanStack Query 5, DOMPurify, date-fns (in `themes/shadcn-prototype/`)

These are different bundles with different chunk hashes — the browser cannot
share them. Total transfer for a user who clicks the wand icon to switch is
**classic bundle + alt-UI bundle in full**.

Tactical fix (low effort):
- Add `manualChunks` in `themes/shadcn-prototype/vite.config.ts` to split out
  `react-vendor`, `query-vendor`, `radix-vendor` (the 20+ Radix packages account
  for a lot of the entry size). Mirrors the TMAIL-259 pattern in the classic SPA.
- Wrap `AdminDashboard` and `CalendarView` in `React.lazy()` inside
  `src/app/routes.ts` and provide a `<Suspense>` boundary in `Root.tsx`.

Strategic fix (medium effort):
- Run both apps off a shared *vendor* bundle by promoting the shared deps to a
  workspace package and using Vite's `external` config. Realistic only if the
  shared-package work for #2 lands first.

### 9. No tests in the alt-UI tree

```
$ find themes/shadcn-prototype -name "*.test.*" -o -name "*.spec.*"
(nothing)
```

The classic SPA enforces (via the trace-check CI gate) that every API module
has at least one consumer; the alt-UI's parallel copy of that surface has
**no** equivalent gate. The drift in `calendar.ts` (finding #2) would have
been caught at PR time by a single `vitest run alt-ui/api/calendar.test.ts`
asserting shape parity with the classic version.

Minimum viable test set:
- One vitest spec per alt-UI API module asserting the function signatures + URL
  shapes match the classic counterpart (can be auto-generated from the diff).
- One Playwright spec walking through `/modern/` → click inbox → open message
  → compose → cancel. Reuse the classic `playwright.config.ts` Firefox project
  and add `webServer: { command: 'npm run dev', cwd: '../themes/shadcn-prototype' }`.

### 10. Misc / quick wins

- **`Sidebar.tsx:31`** — `iconMap: Record<string, any>` should be
  `Record<string, LucideIcon>` (import `LucideIcon` from `lucide-react`). Same
  for `EmailClient.tsx:21` `FOLDER_ICONS: Record<string, string>` — type it as
  the union of icon-map keys.
- **`Sidebar.tsx:79`** — `onFolderChange('inbox')` hard-codes a lowercase folder
  ID, but the real `INBOX` folder ID from the backend is uppercase
  (`'INBOX'`). The branch only fires when a user deletes a "custom" folder
  while viewing it, but it currently sends them to a non-existent route. Fix:
  use `'INBOX'` or look up the actual inbox folder name from `liveFolders`.
- **`EmailReader.tsx:43`** — `const dateRaw = m?.date ?? listItem?.timestamp ?? new Date()`
  followed by `format(timestamp, '...')` on the result. `m.date` is `string | null`
  but `format()` accepts both. Works, but the implicit Date-vs-string coercion is
  worth a comment.
- **`postcss.config.mjs`** — exists at the alt-UI root but Tailwind v4's Vite
  plugin (`@tailwindcss/vite`) processes Tailwind inline. The file is probably
  a no-op leftover from a v3 scaffold.
- **`themes/shadcn-prototype/dist/`** — gitignored (good), 560 KB. Safe to delete
  between rebuilds.
- **`themes/shadcn-prototype/src/components/figma/ImageWithFallback.tsx`** — never
  imported by anything in `src/`. Likely Figma Make scaffolding. Safe to delete.

## Bottom line

The alt-UI's brief (a polished shadcn-based theme served at `/modern/`) is being
met — every feature on screen reads/writes the real Postgres-backed Axum
backend, the auth handoff is clean, and the bundle is self-contained. The
*sustainability* of the prototype is the next concern: the duplicated API
client is already drifting (TMAIL-269), the bundle is monolithic, and there's
no test gate on contract compatibility. The fixes are small and well-scoped —
the highest-ROI single move is the workspace-package extraction (finding #2),
which also unlocks the shared-auth-decode work (#6) and removes the
recurring "did we update both calendar clients?" risk.
