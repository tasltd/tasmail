1. Project Overview & Objectives

TASMail is a webmail interface that proxies IMAP/SMTP for the browser using the user's encrypted credentials. Users sign up for a TASMail account, then attach credentials of their existing mail server (Gmail, Outlook, Zoho, FastMail, ProtonMail Bridge, corporate Exchange, etc.). TASMail never stores email — it proxies in real time.

Key Features

  • Public signup + landing pages
  • Onboarding wizard with 11 popular IMAP presets (Gmail, Outlook, Yahoo, Zoho, FastMail, iCloud, ProtonMail Bridge)
  • Per-user IMAP/SMTP configurations (migration 055_imap_configurations.sql, 042_byo_smtp.sql)
  • Synthetic byok.tasmail domain for signups without admin pre-creation (migration 056_byok_signup.sql)
  • BYOK signup at GHS 1.00/GB·month (≈ $0.07 USD, GHS 5 monthly minimum)
  • Enterprise tier (single-tenant, SAML/OIDC, on-prem option)
  • Push notifications, scheduling, snooze, calendar (ICS), DLP, phishing scanning
  • Alt-UI theme (shadcn/ui + Radix + Tailwind) served at /modern/
  • Flutter mobile app (Android/iOS) with localization (Twi, Ewe, Ga, Hausa)

2. UI/UX Flows

2.1 Public Landing & Signup

  • Landing page: / → LandingPage.tsx — highlights BYOK positioning, pricing (/pricing), security
  • Signup page: /signup → SignupPage.tsx → POST /api/auth/signup — returns JWT pair
  • Onboarding wizard: /onboarding → OnboardingWizard.tsx — guides user through IMAP config test, SMTP test, credential save

2.2 Auth Flows

  • Login: /api/auth/login → JWT access (15min) + refresh (7days) tokens stored in localStorage
  • Refresh: /api/auth/refresh — rotates access token using refresh token
  • SAML/OIDC callbacks: /api/auth/saml/*/login, /api/auth/oidc/*

2.3 Mail Client Surfaces

  • Message List: FolderTree ↔ MessageList — IMAP IDLE push, unread count polling
  • Message View: MessageView — renders email with TipTap composer HTML, DOMPurify sanitization
  • Compose: Composer (TipTap) → POST /api/messages/send → scheduled send (/api/messages/schedule) / snooze (/api/messages/snooze)
  • Search: GET /api/search — full-text across From/To/Subject/Content
  • Folder operations: List, create, rename, delete folders → /api/folders, /api/folders/{folder}/messages
  • Attachment download: GET /api/attachments/{id} — signed token-based download
  • Shared files: GET /api/shared-files/{token} — large file sharing

2.4 Settings

  • Contacts, signatures, calendar, billing, AI config, DLP, LDAP, SAML, retention, branding
  • Per-organizer ICS UID on calendar events (migration 072)
  • Per-account brute-force lockout (migrations 073)

2.5 Alt-UI Theme

Standalone Vite + React app on shadcn/ui + Radix + Tailwind, wired to production backend. Routes: EmailClient + EmailList + EmailReader + ComposeModal, CalendarView, AdminDashboard. Trigger via wand-icon in TopBar or /modern/index.html#/....

3. Edge Cases & Error Handling

3.1 Authentication Failures

  • Invalid IMAP/SMTP credentials → graceful error on onboarding wizard test step
  • JWT refresh failure → auto-redirect to re-login; refresh middleware sets app.current_user_id RLS context
  • Token expired → 401 auto-refresh via Axios interceptor in api/client.ts

3.2 IMAP/SMTP Server Errors

  • IMAP IDLE disconnect → exponential backoff reconnect; fallback to polling every 30s
  • SMTP send failure → retry queue (email_scheduler), dead-letter to queue with retry count
  • TLS cert validation errors → show informative message; do not silently accept invalid certs
  • Connection timeout → user-configurable timeout (default 30s) with cancel option

3.3 Quota & Storage

  • Quota exceeded → block send; show quota bar in TopBar; serve /api/quota for details
  • Large attachment (>25MB) → compress via ImageMagick (config IMAGE_COMPRESSION_ENABLED); reject if still >25MB
  • Mailbox size near limit → serve quota warnings at login; incremental Maildir rsync backup (per BACKUP-RESTORE.md)

3.4 TLS & Certificate Errors

  • Self-signed certs → user prompted to accept or use ProtonMail Bridge/BYOK-trusted certs
  • Cert expiry → pre-warn at 7 days remaining; block after expiry with clear message
  • Mixed content (HTTP inside HTTPS) → block; enforce TLS everywhere

3.5 Multi-Tenancy & RLS

  • Row-Level Security on by default → ad-hoc psql queries require SET app.current_user_id = '';
  • Tenant-scoped tables: emails, contacts, signatures — RLS enforces per-user isolation
  • Cross-tenant data leak prevention → service layer enforces @CurrentTenant filtering; direct Domain.static calls bypass RLS (prohibited per controller-service-calls.md)

Key Integration Points

  • IMAP IDLE bridge: async-imap → Dovecot; source of truth for mail data
  • PostgreSQL: Metadata only (users, contacts, signatures, billing, AI config); sqlx online mode (no .sqlx/ cache)
  • Row-Level Security: Auth middleware sets app.current_user_id per request; ad-hoc DB inspection needs it
  • JWT: Access (15min) + refresh (7days); signs JWTs + derives AES-256-GCM key for DB-stored secrets (rotation invalidates all refresh tokens + encrypted columns)
  • Encryption service: 32-byte key derived from JWT_SECRET; encrypts IMAP/SMTP passwords, payment provider credentials
  • Queue processor: BYOK — loads per-user SMTP config from smtp_configurations, decrypts with JWT-derived key; claim_batch with FOR UPDATE SKIP LOCKED
  • Billing rollup: Daily by default (env TASMAIL_BILLING_ROLLUP_SECS); per-account brute-force lockout (5 attempts/15min/15min lockout)
  • Push notifications: FCM/APNs/Web Push config optional; credentials from env vars
  • Rspamd client: Spam filtering integration

9. RIPUIF Compliance

9.1 Research at Story Level (MANDATORY)

Research happens once, at the parent story/epic level, covering every leaf including edge cases. Leaves inherit the R-gate decision; do not re-open out of nerves. Gate re-opens only on contact (implementation surprise contradicting research).

9.2 Online Search Decision

Online search required when: external fact governs correctness, design depends on third-party behavior, implementation surprise, reversal/inconsistency, named already-solved problem (pagination, auth, cache invalidation), one-way door with unknown options.

Online search NOT required when: answer in codebase + probe would settle it, memory playbook/existing research records it, mechanical change (rename, dead-code deletion, lint autofix, typo), user specified mechanism foreclosing alternatives.

9.3 The R-Gate Records

Story document must contain: Validate/Research/Investigate (once, for whole story), section per leaf (decisions + why), edge cases across whole story (seams between leaves), files table (what each leaf touches), sources (primary with URLs), implementation record appended per leaf as it lands.

Organization: tasltd; Environments: Production soupmarkets.com, Demo demo.soupmarkets.com, Edge edge.soupmarkets.com

Available Projects

  • soupmarkets-web — Grails backend (primary)
  • soupmarkets-spa — Angular SPA (if configured separately)
  • soupmarkets-mobile — Flutter mobile app (if configured)

Common Query Patterns

  • File upload errors: query: "is:unresolved message:*upload* OR message:*file* OR message:*multipart*"
  • Authentication errors: query: "is:unresolved message:*auth* OR message:*login* OR message:*token*"
  • Database errors: query: "is:unresolved message:*database* OR message:*sql* OR message:*hibernate*"
  • API errors: query: "is:unresolved transaction:/rest/*"
  • Multi-tenancy errors: query: "is:unresolved message:*tenant* OR message:*tenantId*"
  • PDF/Report generation errors: query: "is:unresolved message:*pdf* OR message:*wkhtmltopdf* OR message:*report*"
  • Email sending errors: query: "is:unresolved message:*email* OR message:*smtp* OR message:*mail*"

Workflow: Investigating Production Errors

  1. Search for recent issues: is:unresolved age:-24h, sortBy freq
  2. Get issue details: get_issue_details with issueId
  3. Analyze with AI (optional): analyze_issue_with_seer
  4. Search related events: search_events with error keyword from issue
